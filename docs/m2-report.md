# M2 任务服务本机验收

日期：2026-11-04。客户端 `0.1.0.dev3`，内核 `0.1.0.m2-dev3`，协议 v2，数据库 schema v3。上游固定提交仍为 `75a99d6fc46e15c4b994d5245ea4518404088c99`。

## 实现结果

- 默认最多两个常驻独立进程，每个同时执行一项任务；完成后复用，异常/取消时回收进程树。FIFO 排队、活动输入去重、平台限流冷却，启动失败有退避和上限。
- 启动握手核对协议、内核版本及上游 SHA；每 2 秒心跳，默认 15 秒超时，启动允许 20 秒。先协作取消，2 秒后由 Job Object 强制结束；提交授权后的任务不可取消。
- 任务与 attempt 分离，重试建立新记录；revision、attempt 和事件序号共同防止旧消息覆盖新执行。每次执行记录版本、PID、错误、时间和加密的连接配置快照。
- 数据库迁移先备份为 `tasks.sqlite3.pre-v3.bak`；事务更新任务/执行/输出，拒绝未来版本。重启保留排队任务，运行中的任务标记中断，提交中的任务重新校验。
- worker 先生成包含 SHA-256 的清单，请求客户端提交授权；数据库记录随机令牌后才允许原子重命名。客户端后台核对令牌、路径、完整文件集合及哈希，成功才记录完成。
- 临时目录有任务与执行所有权标记，清理拒绝符号链接和 Windows junction。完成/取消立即排队清理；失败/中断保留 7 天，文件占用时 60 秒后重试。清理只作用于专属工作目录，不删除最终作品。
- 任务详情显示最近执行历史；主界面保留现有 Windows 原生窗口与 Fluent 风格导航，完整交互改进进入 M3。

## 验证证据

完整回归命令：`pytest tests upstream-ParseHub/test -q`，结果 **161 passed、104 subtests passed**，无警告。`ruff check src tests scripts packaging` 通过。

测试覆盖进程复用、两进程并发上限、FIFO、去重、崩溃替换、心跳超时、协作取消、关闭进程树、配置快照加密、迁移备份/未来版本、事务回滚、旧执行事件、提交恢复、文件篡改拒绝、目录隔离和清理重试。

首次冻结样本暴露 Windows CRT 的阻塞 stdin 读取与 NumPy 首次加载锁冲突。已改用 Windows `ReadFile` 读取管道，避免占用 CRT 描述符锁，并新增首次加载原生依赖期间仍有心跳且可取消的回归。最终冻结包不含临时栈诊断代码。

真实用户抖音样本：源代码控制器调用冻结内核，在 PATH 仅 System32 的情况下完成预览和下载，耗时约 5.27 秒；两个 attempt 复用同一 PID。输出 17,240,754 字节，SHA-256 为 `3f5289db4a46fc30e9a0a0cab60db5d9ef6d3a6a2f5f09cade8e072d3540576b`，与 M0/M1 相同。证据：[真实样本记录](../review/m2-live-sample.json)。

冻结客户端启动、内核描述、捆绑工具自检、同一客户端加载 E1/E2 均通过：[冻结检查](../review/m2-packaged-checks.json)。E2 使用相同代码与模拟版本号，只证明版本隔离，不代表真实更新/回滚已实现。

测试包：`dist/m2/MediaDownloader-M2.zip`，或在工作区运行 `run-m2.ps1`。中文新目录解压默认内核发现检查记录在 [归档检查](../review/m2-archive-check.json)，大小与 SHA-256 在 [产物清单](../review/m2-artifacts.json)。

## 后续阶段与限制

M3 继续完成媒体预览、格式能力呈现、队列/历史交互、主题、高对比度、键盘与 DPI 验收。M4 实现签名内核更新源、上游同步流水线、安装切换和回滚；当前协议 v2 是版本边界基础，M1 客户端不会兼容 M2 内核。

这是未签名本地测试包。干净 Windows/虚拟机验证按用户要求延期，没有执行 Hyper-V 操作。真实平台覆盖仍仅有一条抖音样本；完整平台、凭据与发行验证继续保留到发布前。
