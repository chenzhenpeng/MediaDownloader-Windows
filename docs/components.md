# 应用包、ParseHub 解析组件与执行运行环境

## 发布边界

| 发布单元 | 包含 | 更新方式 |
| --- | --- | --- |
| 应用包 | WinUI 界面、Python 任务服务、SQLite/DPAPI 管理和更新器 | x64 安装程序整体升级；GitHub Actions 生成待验收草稿 |
| ParseHub 解析组件 | 固定提交的 ParseHub 源码、经过审核的 adapter.py、许可证 | 小型签名包，复用匹配的执行运行环境 |
| 执行运行环境 | worker、Python、精确依赖、基线解析组件、yt-dlp、FFmpeg/ffprobe | 完整签名包；低频升级，不随每次解析器修复重发 |

FFmpeg/ffprobe 成对固定，yt-dlp 的实际文件哈希也锁定。当前不提供独立的第四套工具更新器。任务数据库、凭据、下载队列和更新信任配置属于应用包，不由解析组件修改。

## 发现与兼容选择

新客户端从固定 `channel-stable/catalog.json` 和独立签名发现更新，不依赖仓库 Latest。目录由发布公钥认证，包含每个候选的原始签名清单；签名、有效期、渠道、客户端/协议/架构范围、最大目录大小及候选数量均受检查。

运行环境和解析组件各自比较版本，只允许正常升级到更高版本。运行环境包含的基线解析器也不能低于当前解析组件。显式本地回滚是单独路径，不降低防重放记录。无法比较的历史版本不猜测更新方向，需通过客户端迁移。

目录可以保留多个运行环境对应的候选。先选择能复用当前环境的解析小包；没有兼容小包时可选择更新的运行环境，再在下一次检查获取匹配的解析包。暂不一次自动安装多个未验证组合。

## 原子组合与恢复

解析包声明 `requires_runtime_id`，安装时将匹配的、已验证的运行环境身份记在包目录的 `runtime-reference.json`。不能引用另一个解析包作为运行环境。加载和启动恢复时重新认证所引用运行环境的签名及文件清单。

应用仍只原子切换一个 `current` 指针；该指针代表完整可运行组合。`pending`、`last_good` 和健康标记提供断电恢复及失败回滚。保留当前和上一组合，并保留它们引用的运行环境；不会在解析包仍使用环境时清理环境目录。

解析小包在 worker 导入 ParseHub 和适配层之前加载。允许覆盖的应用模块仅为明确审核的 `media_downloader.adapter`；其 ABI 单独校验，数据库、更新器、网络边界等应用模块不随解析包替换。模块不写入 .pyc，以保持安装文件不可变。

运行环境契约包含 Python ABI、目标架构、IPC、加载器 ABI 和 worker 的依赖闭包；任务服务 Qt 依赖不参与。依赖或 ABI 不匹配的解析包会被拒绝，不由客户端临时运行 pip 安装依赖。

## GitHub 发布流程

- `application-release.yml`：获取已签名运行环境并验证、构建原生应用与 x64 EXE，生成客户端草稿，实际桌面安装验收后发布。
- `engine-release.yml`：使用 `media-tools-lock.json` 的同一份工具锁，只构建执行运行环境，经冻结自检后在受保护环境签名，生成草稿。
- `parser-release.yml`：获取兼容的已签名环境，只打包 ParseHub 和适配代码，用真实冻结环境自检后签名，生成草稿。
- `component-catalog.yml`：审核后的组件发布后，验签并生成固定渠道目录。组件包不可变，目录独立递增序号。
- `component-catalog-renew.yml`：每周认证并续签目录和内嵌清单，保持包哈希不变；不能理解的目录条目导致停止续签，不静默丢弃。
- `upstream-watch.yml`：定时生成上游候选 PR，重放本地补丁并运行验证；不会直接将作者提交推送到用户电脑。

旧客户端仍保留旧整包发现路径。新组件发布不修改仓库 Latest，不让应用包或目录发布覆盖旧客户端入口。

## 当前验收

运行环境 0.1.5、解析组件 0.1.6 已发布，并通过冻结客户端实际 HTTPS 小包安装与回滚；目录续签工作流也已在线验收。解析组件约 167 KB，运行环境约 144.6 MB；后者仅在依赖/worker/工具变化时下载。源码非交互回归为 305 项测试及 104 个子测试。详细证据及仍未覆盖的构建边界见 [发布验收记录](./components-release-2026-11-05.md)。
