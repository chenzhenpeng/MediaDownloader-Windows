# M4 内核更新本机工程验收

日期：2026-11-04。客户端 `0.1.0.dev5`，内核 `0.1.0.m4-dev5`，IPC v2，任务数据库 v3。M0–M3 归档保留。

## 实现结果

维护端已提供四组可重放补丁和哈希目录：传输/结果、工具、平台边界、Windows 测试。`sync_upstream.py` 同时读取默认分支与最新 Release，只准备候选、重放补丁和生成接口/依赖变更报告，不执行候选代码。补丁重放与外层 Git 仓库隔离，避免 CI 检出环境中误改客户端文件；候选归档拒绝 Git 管理目录。

已编写定时/手动候选草稿 PR、只读 Windows 验证、受保护环境签名和草稿 Release 三份工作流。官方 Actions 固定到查询过的提交。签名密钥只用于最后的受保护签名步骤，新上游代码不在持有写 Token 的候选准备步骤中导入或构建。

客户端已接入：

- 原始 UTF-8 清单的独立 Ed25519 签名、受信任公钥和渠道；架构、IPC、客户端版本、时间有效期与序号检查。
- 严格大小限制、HTTPS 来源/跳转允许列表、取消、磁盘预算、整包 SHA-256、签名绑定的逐文件清单。
- 解包拒绝绝对/越界/保留名/ADS、重复及大小写冲突、符号链接/junction、加密条目与超额解压。
- 候选模块/工具/离线下载隔离自检，Job Object 管理进程树；健康标记缺失或损坏的候选不能成为启动版本。
- 下载、哈希、解包和自检在后台执行；候选准备后暂停新任务派发，等待活动 attempt 结束，再关闭旧闲置 worker、原子记录 pending、启动新 worker。
- 新 worker 握手成功才确认 current；启动失败恢复旧内核。重启检查 pending、签名及文件清单，失败回退上一版本或随包基线。
- 手动回滚、版本锁定、仅提示的每日检查设置；回滚不降低最高 sequence，已执行任务保留原内核版本。
- 当前/上一版本保留及无引用旧版本清理；更新锁、下载会话锁和失败 staging 隔离。

冻结客户端首轮验收发现自检后重命名 Windows 候选目录被拒绝。已改为“先安置已验证文件，再从固定位置自检并写健康标记”，指针在成功前始终引用旧版。另补充损坏信任配置、健康记录与指针的恢复验证。

## 验证证据

测试结果与命令见 [完整回归记录](../review/m4-tests.json)，包含签名/哈希/过期/重放/不可变版本、磁盘与取消、恶意归档、损坏记录、活动任务期间等待切换、启动失败回滚、版本锁定和外层 Git 隔离等专项。静态检查 `ruff check src tests scripts packaging` 通过。

真实冻结链路：同一个冻结客户端进程，从 E1 `0.1.0.m4-dev5` 检查本地签名 feed、安装完整 E2 `0.1.0.m4-dev5-e2`、握手切换，再回滚 E1；客户端没有重启。回滚后最高 sequence 仍为 **7**，pending 清空。证据：[冻结升级与回滚](../review/m4-frozen-update.json)。内核 ZIP 约 **300.84 MiB**；这是包含工具的整包更新，当前不做差分。

E2 解析代码与 E1 相同，仅用不同版本字段验证机制；签名使用只存在于本地验收过程的临时测试密钥。默认客户端没有加入测试公钥或测试 feed。

四组补丁在原始审查提交上重放，13 个文件与当前 vendored 代码等价：[补丁重放](../review/m4-patch-replay.json)。本次只读查询默认分支及 Release `v2.4.0` 均指向 `75a99d6fc46e15c4b994d5245ea4518404088c99`，尚无须更新的上游 SHA：[上游查询记录](../review/m4-upstream-latest.json)。

用户公开抖音样本在受限 PATH 下继续完成封面及完整下载，约 4.83 秒，17,240,754 字节，SHA-256 与前几阶段一致：`3f5289db4a46fc30e9a0a0cab60db5d9ef6d3a6a2f5f09cade8e072d3540576b`。证据：[真实样本](../review/m4-live-sample.json)。冻结自检与独立内核加载：[冻结检查](../review/m4-packaged-checks.json)；最终中文目录 ZIP 解压：[归档检查](../review/m4-archive-check.json)。

**线上更新源、仓库 Actions、Environment 审批与生产签名密钥尚未配置或部署。** 当前更新页正确显示未配置来源，不自动下载内核、不显示虚假最新版。已经准备好可审查的工作流和[具体部署配置](./release-setup.md)，需要实际发布仓库、生产公钥及受保护签名环境后才能形成线上分发。
